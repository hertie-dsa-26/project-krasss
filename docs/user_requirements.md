# Application Requirements Document

## Overview

The application will provide a web interface that presents and analyzes data at the city level in the United States on weather patterns, health outcomes and demographic profiles between 2013 and 2023. It will provide an interactive interface to allow users to explore associations between the data points visually and will provide at least one predictive machine learning model linking the data sets. The application will also provide supporting documentation and links to external resources to provide background and context on each of the variables used. The goal of the application is to provide urban policy professionals a visual data explorer that they can use to inform policy design, specifically with respect to the impact of changing weather patterns on everyday health outcomes and behaviors. As a secondary goal, the application can also be used by researchers for initial exploratory analysis, as well as by the public to get a snapshot of the situation in a particular city. 

## Stakeholders/Users

| Name / Group Name | Role / Overview of Needs |
|----------|----------|
| Urban policy practioners | Urban policy practitioners who develop policy in cities to support needs of the inhabitants. This includes both short-term responses to events such as acute weather changes as well as planning for future adaptation needs based on longer-term trends and expected impact of continuous changes. To do so, they need to understand both the historical trend in the association between weather changes and health outcomes, as well as what that may mean for the future under different scenarios so that they can plan policies accordingly. |
| Climate / health / urban policy researchers | Researchers who want to undertake more in-depth analysis of the links between changing weather patterns and everyday health behaviors and outcomes at the city level. While the interface will not provide sufficient robustness for an in-depth study – particularly for causal inference – it can provide an initial starting point for exploratory data analysis to understand the trends among the different indicators to facilitate both background research and inform research question design. Along with toggling with trend analysis, researchers also need to understand the detailed methodology behind the calculations and be able to access the data in case they want to use it for any further needs. |
| General public | Members of the public who want to understand more about the situation in a particular city / type of city. This could be based on where they live right now or potentially a city / area they are planning to move to. Their focus is likely to be most on the current situation as well as any future predictions to inform any decisions they might want to make about place of residence / necessary adaptations they might need to make. They would need the information to be easily accessible and understandable to non-experts and would not be very focused on the technicalities of the calculations. |

## Detailed User Needs

| ID | User Need Description | Relevant User |
|----------|----------|----------|
| **Documentation and Background** |
| UN-01 | Users should be able to clearly understand the main purpose of the app to see if it meets their needs quickly and also be given basic instructions on how to use / navigate it | Policy practitioners, researchers, public |
| UN-02 | Users should be able to get a quick overview of the datasets used for the analysis, access a quick list of the variables included and be able to navigate to the external data sources directly from the app if needed | Policy practitioners, researchers, public |
| UN-03 | Users should be able to familiarize themselves with the main findings / existing knowledge around the themes covered by the application for context and background, as well as to help them interpret the data. The literature review should be in an easy-to-understand language for non-technical audiences and should link to external resources that users can navigate to easily. | Policy practitioners, researchers, public |
| UN-04 | Users should be able to read through a semi-detailed explanation for each variable to be able understand what it implies. This should also be in a non-technical language for general audiences. It should exist at least in the documentation and background page but possibly also be accessible easily via the data analysis pages to make it easier for users to understand a variable without having to navigate back and forth between pages. | Policy practitioners, researchers, public |
| UN-05 | More technical users should be able to get a more in-depth background on the measurement and statistical methods used for estimation (particularly for modelled variables such as those from CDC Places). While the explanation does not have to be as detailed as available in the original datasets, they should provide a general overview and then link to the more detailed explanations | Researchers (potentially policy practitioners) |
| UN-06 | More technical users – especially researchers – should be able to read about the methods behind the machine learning algorithms used for predictions, especially any major assumptions taken during the design of the algorithm, so that they can interpret results with any caveats needed, while also be able to reuse the algorithms for their own work if appropriate. This information should also include information on model evaluation statistics and development methodology. | Researchers |
| UN-07 | Users should clearly be able to understand the limitations associated with any of the variables used and the analysis done with them so that they are clear about the level of implications that can be drawn from the analysis to meet their own needs. There should be a general section on limitations in the documentation page but any variable or chart-specific limitations / warnings should also be flagged in the variable description / next to the concerned visual. | Policy practitioners, researchers, public |
| **Exploratory Analysis** |
| UN-08 | Users should be able to look at spatial analysis of the variables in a central map that shows all geographic units selected for analysis. | Policy practitioners, researchers, public |
| UN-09 | Users should be able to narrow down on specific geographies – such as a county / a city or a group of locations – based on their needs. The map – and all other analysis – should get filtered (as appropriate) based on the geographic unit(s) selected. | Policy practitioners, researchers, public |
| UN-10 | Along with the choice of locations, users should be able to filter for the specific input and output variables they are most interested in. These should be grouped under three themes – weather, demographics and health – to facilitate choice, and all visuals should be filtered (as appropriate) based on selections made by users. They should be able to select both one and multiple options from the variables. | Policy practitioners, researchers, public |
| UN-11 | Users should be able to see the values of the variables selected when they hover over a specific geographic unit on the map. | Policy practitioners, researchers, public |
| UN-12 | Users should be able to see the most recent value of the variable(s) selected as well as the average value over the entire time of analysis. | Policy practitioners, researchers, public |
| UN-13 | Users should be able to filter the years that analysis is done for by choosing either one or multiple years of interest. All visuals should be filtered down based on the years selected. | Policy practitioners, researchers, public |
| UN-14 | Users should be able to see time series charts for the variables selected under the map to see average trends over time. There should be three side-by-side line charts grouping variables together under the three thematic areas – weather, demographics and health – to facilitate ease of interpretation. | Policy practitioners, researchers, public |
| UN-15 | Users should be able to see overall summary statistics for the variables selected in a simple tabular structure under each time series chart. The summary statistics should provide users a basic overview of the distribution of the data for each variable selected (average value over the entire dataset, average value for a geographic concentration / climate zone, distributional aspects such as range or a basic density plot). | Policy practitioners, researchers |
| **Machine Learning and Predictions** |
| UN-16 | Users should be able to view a set of default predictions for future trends (health outcomes influenced by scenarios of input variable changes) based on average values across the model. These trends should be shown in line charts over time with areas of uncertainty highlighted. | Policy practitioners, researchers, public |
| UN-17 | Users should be able to choose a specific geographic area of focus, and the prediction chart should filter down to show those results as appropriate. Predictions should stay robust, however, given the likely smaller sample of data one might be working with if a specific city is chosen. In such cases, analysis should potentially group lower-level locations into similar geographic clusters to make predictions somewhat reasonable and also display a clear warning about the extent of interpretation possible when very specific locations are chosen. | Policy practitioners, researchers, public |
| UN-18 | Beyond the default scenario(s) used for the chart, users should be able to select their own variables of interest (again from the three groups highlighted above) to set up their own scenarios for analysis. | Policy practitioners |
| UN-19 | Users should be able to view the outcomes of the scenarios they set up visually in a way that facilitates comparison. This should be done in a line chart, with different colored lines showing trends for different scenarios. | Policy practitioners |
| UN-20 | Users should be able to interpret model outputs as easily as possible to facilitate decision-making (both at the policy level as well as at the individual level). All variables should be shown in easy to understand units (as opposed to standardized values) and any complex statistical numbers should be accompanied by explanations or with a note that they are only relevant for more technical audiences. | Policy practitioners, public |
