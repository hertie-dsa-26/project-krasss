Documentation

HALCYON is a Flask-based web application for exploring relationships between weather patterns and health outcomes across U.S. counties (2013–2023), using data from NOAA, CDC, and the U.S. Census.

Data sources

  • NOAA — National Oceanic and Atmospheric Administration
    This data comes from the National Ocean and Atmospheric Administration (NOAA) Global Summary of the Year, and supplies the Halcyon app with temperature and weather data from across the United States. This data set provides 16 variables for this app, and the geographic basis for a 17th.
    https://www.ncei.noaa.gov/cdo-web/
  • CDC Places
    The CDC Places dataset supplies the Halcyon app with health data at the county level, including the app's predicted outcome variables: stroke incidence, mental health quality, physical health, asthma incidence, and sleep.
    https://www.cdc.gov/places/tools/data-portal.html
  • U.S. Census Bureau
    The U.S. Census Bureau dataset supplies the Halcyon app with demographic information at the county level, covering twelve variables used to eliminate non-climate variations between health outcomes.
    https://www.census.gov/data/developers/data-sets/acs-5year.html

Known issues & limitations

While every effort has been made to make the models as robust as possible, several limitations exist that should be taken into account before drawing any conclusions from the predicted values.

  • Data
    The dataset used to train the models only contained data for 10 years, which is a relatively short time period for slow moving variables such as health outcomes and annual weather patterns. As a result, models are heavily biased towards events in this short time period and may not accurately reflect more long-term trends.
  • Models
    Not all models are equally robust. As the technical documentation shows, while models for Stroke, Mental Health and Asthma show lower error rates for the available data, Physical Health and Sleep both perform poorly and findings from those two models should be assessed with heavy qualifications.
  • Confidence Intervals
    Due to limited data availability, a trade-off was made during model training between better point predictions and better accuracy of confidence intervals by retraining models on a set of the data that was used to calibrate prediction intervals. Diagnostics in the technical documentation reveal that this has not significantly affected CI coverage, with coverage only being poor for the two weaker models (Physical Health and Sleep) but users should still assume that existing confidence intervals may provide more optimistic coverage than may be desired.

Architecture overview

The ML pipeline is split across eight files. No external ML libraries (e.g. scikit-learn) are used for the core model; all components are implemented from scratch using NumPy and Pandas. XGBoost is used for the SLEEP target only.

Training pipeline

A separate model is trained for each health target by tune_and_evaluate() in train.py. The steps are the same for every target:

StepWhat happensModule
1. Data prepprepare_data() drops all other health outcomes and non-feature identifiers, then splits into X, y, and year labelssplitter.py
2. Fold creationSplitter.time_series_splits() builds expanding-window CV folds (2014→2015, 2014–2015→2016, … 2014–2021→2022); 2023 is held out as the test set throughoutsplitter.py
3. Grid searchCrossValidator scores each hyperparameter combination using the last 3 stable folds; early folds are skipped because the training set is too small before 2018cross_validator.py
4. Final fitBest model is fit on 2013–2021, calibrated on 2022, retrained on 2013-2022 data, and then evaluated on the held-out 2023 test settrain.py
5. SaveModel + fitted preprocessor are pickled together as models/{TARGET}.pkl for the Flask app to loadtrain.py

Preprocessing

Preprocessor coordinates three components via composition (not inheritance), applied in order: encode → impute → scale. A fresh instance is created inside each CV fold to prevent statistics from leaking between folds.

ComponentWhat it does
OneHotEncoderConverts climate_type_short (the only categorical column) into binary indicator columns. Drops the first category per column to avoid multicollinearity. Fit on training data only — unseen categories in val/test are handled using training categories.
SimpleImputerReplaces NaNs with column means learned from training data. Most columns have <10% missing.
StandardScalerStandardizes each feature to mean=0, std=1 using z = (x − μ) / σ. Required because the RFF kernel is sensitive to feature scale. Constant columns (std=0) are left unchanged.

The fit_transform() method is used on training data; transform() applies the saved statistics to validation and test data. This separation is the primary guard against data leakage.

Random Fourier Features (RFF) model

Kernel Ridge Regression (KRR) solves α = (K + λI)⁻¹ y exactly, but this requires building and inverting an n×n kernel matrix — O(n³) in time and O(n²) in memory. For large datasets this becomes infeasible. Random Fourier Features approximate the kernel implicitly, reducing the problem to ordinary ridge regression on a low-dimensional feature map Z.

Feature map

R random frequencies W are drawn from N(0, 1) and phases B from U(0, 2π), then:

Z = √(2/R) · cos( σ · X Wᵀ + B )

This gives an (n, R) matrix Z such that ZZᵀ ≈ K for the Gaussian kernel with bandwidth σ.

Fitting

Coefficients are solved directly using ridge regression on Z:

coef = (Zᵀ Z + λ I)⁻¹ Zᵀ y

Prediction

ŷ = Z_test · coef

Conformal prediction intervals

After fitting, calibrate() stores nonconformity scores (absolute residuals) on the 2022 held-out calibration set. At inference, predict_interval() computes the finite-sample corrected quantile from Angelopoulos & Bates (2022):

q_level = ceil((1 − α)(n_cal + 1)) / n_cal

The prediction interval is then [ŷ − q, ŷ + q]. This gives a coverage guarantee: at least (1 − α) of test points will fall within the interval.

XGBoost model (SLEEP only)

The SLEEP target uses XGBoostWrapper instead of RFF. SLEEP data is collected every two years, making the training set smaller and noisier. Gradient boosting is more robust to this than the kernel approximation.

XGBoostWrapper trains three models in parallel: a median model (reg:squarederror) for point predictions, and lower/upper quantile models (reg:quantileerror at α=0.025 and 0.975) producing a base 95% quantile interval. These bounds are then optionally narrowed or widened by conformal calibration — the correction takes min(lower, ŷ − q) and max(upper, ŷ + q), where q is the same finite-sample corrected residual quantile used in RFF — to achieve the requested coverage level (default 90%).

ParameterDescriptionGrid searched values
n_estimatorsNumber of boosting rounds100, 300
max_depthMaximum tree depth — controls model complexity4, 6, 8

Model diagnostics

All diagnostic charts are generated by diagnostics.ipynb. The notebook loads saved .pkl models via load_model() from train.py and reproduces the exact 2023 test split used during training.

Model performance varies across outcomes. Stroke has the strongest predictive performance, with an R² close to 1 and low MSE. Asthma and mental health show modest R² values (~0.5). Physical health performs poorly (negative R²), indicating the model underperforms a simple mean prediction. Sleep, modelled with XGBoost, shows moderate predictive performance.

Performance is broadly consistent across all three approaches. The custom RFF and sklearn RFF approximation produce similar R² and MSE values and are substantially faster than exact sklearn KRR. The main divergence is for Physical Health, where the custom RFF shows a slightly more negative R², though all three models perform weakly on that target. Runtime figures exclude hyperparameter tuning and reflect final-pipeline inference only.

Residuals are largely randomly scattered around zero for Asthma, Mental Health, and Stroke, suggesting no systematic bias for those models. Physical health shows a downward bias, confirming model weakness: the model is underpredicting for lower predicted cases, which constitute the majority. Residuals for most targets skew positive, indicating predictions tend to fall below actual values. Stroke residuals are closest to zero, consistent with its high R².

Points close to the diagonal red line indicate accurate predictions. Stroke, Asthma, and Mental Health cluster tightly along the diagonal. Physical Health shows systematic underprediction with points lying above the line throughout the range. Sleep displays range compression: the slope of the predicted-vs-actual curve is much shallower than the ideal diagonal, meaning the model struggles to capture the full variation in sleep outcomes.

Shaded bands are 90% conformal prediction intervals; red dots are actuals sorted by true value. Stroke, Asthma, and Mental Health show strong coverage, with the bands capturing actuals even at the extremes. Physical Health intervals cover all actuals but predictions remain systematically low. Sleep intervals fail to capture actuals at the tails, reflecting the range-compression issue seen in the predicted-vs-actual chart.

Testing

The test suite covers all core pipeline modules across three layers: unit tests, integration tests, and one end-to-end test. Tests are organised into a three-tier folder structure and run with pytest. Each test module imports directly from app/functions so no installation step is required.

Assessment — test_r2_score.py, test_mean_squared_error.py

Verifies the two metric implementations against known hand-computed values. R² returns 1.0 for perfect predictions and 0.0 when predicting the mean. MSE returns the correct average squared error. These are intentionally minimal as the formulas are simple and the tests serve as regression guards.

Preprocessing — test_simple_imputer.py, test_standard_scaler.py, test_one_hot_encoder.py, test_detect_categorical_columns.py, test_preprocessor.py

Each preprocessing component is tested independently and then together through Preprocessor. Key cases covered:

SimpleImputer — replaces NaNs with column means; handles the all-NaN column edge case by falling back to 0 (a NumPy warning is expected here and noted in the test)
StandardScaler — output has mean=0 and std=1; constant columns (std=0) are left unchanged to avoid division by zero; transform() uses training statistics, not test statistics
OneHotEncoder — drops the first category to avoid multicollinearity; handles multiple categories correctly; unseen categories at inference time become all-zeros rather than raising an error
detect_categorical_columns() — returns correct indices for object and category dtype columns; returns an empty list when no categorical columns are present
Preprocessor — end-to-end: imputes and scales numeric data to mean=0, std=1; handles mixed numeric/categorical input; transform() applies the pipeline fitted on training data without refitting

Splitter — test_splitter.py, test_prepare_data.py

Covers data preparation and fold generation:

prepare_data() — keeps the target column in y and drops it from X; drops all other health outcomes and all identifier columns; correctly drops rows where the target is NaN (critical for SLEEP)
Splitter — correctly assigns the last year as the held-out test year and all earlier years as training; time_series_splits() produces expanding windows with the correct train/val arrays at each fold; get_test_split() returns the full training set and the held-out test year

CrossValidator — test_cross_validator.py

Uses a minimal MeanModel stub (predicts the training mean) to test the CV loop in isolation without depending on the RFF model. Verifies that cross_val_score() returns both mse and r2 keys, produces one score per scored fold, and that all scores are finite.

KRR baseline — test_krr.py

Tests the exact Kernel Ridge Regression implementation used as a baseline comparison against the RFF approximation. Verifies that fit() and predict() produce finite outputs of the correct shape, and that the kernel matrix is computed correctly for the Gaussian kernel. This model is not used in the production Flask app but is evaluated in diagnostics.ipynb to benchmark the RFF approximation.

RFF model — test_random_fourier_features.py

Six tests covering the full RFF interface:

rff_features() — output shape is (n_samples, R); results are exactly reproducible given the same seed
fit() — coefficients exist after fitting and have shape (R,)
predict() — returns one prediction per test row
predict_interval() — raises RuntimeError if called before calibrate(); after calibration, lower ≤ predicted ≤ upper for all test points

Scenarios — test__compute_trend.py, test_generate_scenario.py

Tests for the future projection logic used by the Flask app:

_compute_trend() — returns 0.0 when fewer than 3 data points are available; enforces physically consistent slope direction (positive for warming variables like TAVG, negative for cooling variables like HTDD) regardless of the observed trend direction in the data
generate_scenario() — returns the correct future year range; drops all identifier and health outcome columns from the feature matrix; projects warming variables forward by the correct cumulative amount; raises ValueError with a descriptive message when the baseline county/year combination is missing

Basic routes — test_basic_routes.py

Uses Flask's test client to verify that all page routes return HTTP 200 and render without errors. Covers /, /explore, /predict, and /docs. Does not require model .pkl files — tests only that routing and template rendering are functional.

API routes — test_map_data_api.py, test_snapshot_api.py, test_summary_api.py, test_timeseries_api.py

Tests the four JSON endpoints consumed by the explore page's charts and map:

/api/map-data — returns valid GeoJSON with the correct structure; filters correctly by year and variable; returns an error for unknown variables
/api/snapshot — returns county-level summary statistics for a given year; handles missing county/year combinations gracefully
/api/summary — returns aggregated statistics across all counties; response includes expected keys for all five health outcomes
/api/timeseries — returns year-indexed data for a given county and variable; verifies correct year ordering and that only the requested county's data is returned

Prediction page — test_prediction_page.py

Tests the /predict route end-to-end against the running app. Verifies that the page returns HTTP 200 and contains the prediction form with the required fields (county_state, target, scenario); that all five target outcomes and all four climate scenarios are present in the rendered HTML; and that a real POST request for Alameda County returns a results page with predicted value and confidence interval columns and no error message. This test requires the saved .pkl model files to be present.

Navigation flow — test_navigation_flow.py

Simulates a complete user journey through the application using Flask's test client. Verifies that a user can navigate from the landing page to the explore page, apply filters, move to the predict page, submit a prediction form, and reach the docs page — all returning HTTP 200 at each step with no server errors. This is the only test that exercises the full application stack in sequence.
